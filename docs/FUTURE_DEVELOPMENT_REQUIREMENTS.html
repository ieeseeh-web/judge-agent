2기능 요구사항 (Feature Requirements)

1

Phase 1 — 탐지 품질 강화

현재 7개 detector와 10개 메트릭을 확장하고 LangChain 어댑터를 추가

  • FR-101
    Detector 확장
    tool_argument_mismatch, repeated_tool_call, context_hallucination, memory_staleness, goal_drift 5개 신규 detector 추가. 현재 7개 → 12개.
  • FR-102
    LLM Judge 강화
    reference-based LLM judge(기준 run과 비교) 및 reference-free LLM judge(독립 평가)를 지원. 현재 deterministic rule만 존재.
  • FR-103
    메트릭 확장
    task_completion_rate, tool_argument_correctness, context_groundedness 등 추가. ~10개 → ~40개 단계적 구현.
  • FR-104
    Generic LangChain/LangGraph 어댑터
    현재 reference-weblog-jsonl 전용 어댑터 외에 범용 LangChain 트레이스 파싱 어댑터 구현. 실제 LangChain 프로젝트에 Judge Agent 직접 적용 가능.
2

Phase 2 — 사용성 개선

히스토리 조회, 파일 업로드, 다중 Run 비교, 채팅 세션 복원

  • FR-201
    실행 히스토리 조회 UI
    과거 Reference Run 목록을 날짜/fixture/모델별 필터링하고, 특정 run을 선택해 트레이스·결과를 다시 확인. 선택한 run을 Judge / Set baseline 에 재사용.
  • FR-202
    트레이스 파일 직접 업로드
    외부에서 생성된 JSONL 트레이스 파일을 UI에서 업로드하면 Judge Agent가 분석. TraceUploadCard 컴포넌트 기존 존재, 백엔드 연결 필요.
  • FR-203
    다중 Run 비교 대시보드
    2개 run 비교(현재)를 넘어 N개 run을 선택해 메트릭 변화 추이를 차트로 시각화. 반복 실험 시 추세 파악 필요.
  • FR-205
    채팅 세션 히스토리 저장/복원
    Reference Agent 채팅 대화 내역을 저장하고 추후 동일 세션을 불러와 이어서 대화. 현재 페이지 새로고침 시 대화 소실.
3

Phase 3 — 확장성 & 운영

DB 저장소, CI/CD 통합, API 인증, 실시간 스트리밍

  • FR-301
    DB 기반 저장소
    파일 기반(registry.json) → SQLite(단독) → PostgreSQL(다중 사용자). 동시 요청 run_id 충돌 문제 근본 해결.
  • FR-303
    CI/CD 통합 강화
    GitHub Actions / GitLab CI 워크플로 템플릿 제공. PR 머지 전 prompt regression 자동 실행 및 PR 코멘트 게시.
  • FR-305
    실시간 스트리밍 응답
    LLM 토큰 생성 시 채팅 UI에 실시간 표시. 26B 모델 사용 시 응답 대기 시간 긴 UX 문제 해결. SSE 또는 WebSocket.
  • FR-306
    인간 피드백 루프
    Judge 분석 결과에 동의/반박 피드백을 수집·저장해 detector 임계값 조정에 활용. Judge 정확도 지속 개선.

관련 FRFR-101

관련 FRFR-104
입력LangChain JSONL 트레이스 또는 LangSmith Export
처리이벤트 정규화 → SimpleAgentRun 변환

FS-201Reference Run 히스토리 조회 UI

표시 항목run ID, 실행 시각, 사용 모델, 상태(SUCCEEDED/FAILED), eventCounts 요약

백엔드GET /api/reference/runs + 필터 파라미터 ?fixture=&model=&status=&from=&to= 추가
